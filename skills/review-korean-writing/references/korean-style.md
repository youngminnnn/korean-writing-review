# 한국어 표현과 의미 보존

## 문맥에서 판단할 표현

| 관찰할 문제 | 판단과 개선 방향 |
|---|---|
| 번역투·과도한 명사화 | 조사와 명사가 겹쳐 행위가 흐려졌을 때 동사 중심으로 풀어 본다. ‘통해·대해·기반으로’를 금지어로 삼지 않는다. |
| 피동·행위 주체 | 이중 피동이나 불필요한 우회를 줄인다. 행위자가 원문에 없으면 만들어 넣지 않는다. 결과가 중요한 설명의 피동은 유지한다. |
| 추상 어휘와 비유 | ‘관점·구조·기반·축’ 등이 무엇을 뜻하는지 독자가 알 수 있는지 본다. 실물 용법, 전문 개념, 효과적인 비유는 보존한다. 구체화할 사실이 없으면 질문한다. |
| 공허한 평가·결론 | ‘중요하다·의미가 있다’ 뒤에 실제 이유가 있는지 살핀다. 원문에 없는 성과나 이유를 만들어 구체화하지 않는다. |
| 기계적인 병렬·반복 | 반복이 정보 탐색에 도움이 되는지 본다. 절차·대안 비교·주의사항의 번호와 불릿은 유지한다. |
| 접속 표현 | 논리 관계를 정확히 나타내는지 판단한다. 횟수를 줄이려고 원인·대조·예외 관계를 없애지 않는다. |
| 리듬·종결형 | 정보의 밀도와 읽기 어려움을 개선한다. 문장 길이·어미를 다양하게 만들기 위해 의미나 격식을 바꾸지 않는다. |
| 유보·가능·의무 | ‘일 수 있다·해야 한다·해도 된다’의 차이를 보존한다. 표현이 길다는 이유만으로 단정으로 바꾸지 않는다. |

## 수정 전후 대조

### 용어 선택은 독자의 이해를 기준으로

원문 용어가 자연스럽고 정확하면 유지한다. 이는 영어 약어나 표준 전문 용어에만 한정하지 않는다. 업계 외래어, 제품의 기능명, 조직이 사용하는 이름도 포함한다. 낯설어 보이는 단어라는 이유로 한국어 직역을 강제하지 않는다.

1. 독자와 맥락에서 뜻이 통하면 그대로 둔다. 개발자 대상의 ‘캐시·롤백·배포 파이프라인’을 ‘임시 저장소·뒤로 굴리기·배포 관로’로 바꾸지 않는다.
2. 비전문가에게 설명이 필요하면 용어를 살리고 처음에만 풀이한다. 예: ‘롤백(문제가 생긴 변경을 이전 상태로 되돌리는 작업)’. 실제 제품의 정의와 맥락에 맞춰 풀이한다.
3. 한국어 표현이 더 익숙하고 같은 뜻이면 선택지로 제안할 수 있다. 사전 번역이 있다는 이유만으로 치환하지 않는다. 여러 곳의 용어를 바꿀 때도 문서 전체의 일관성과 개념 구별을 확인한다.
4. ‘프롬프트·컨텍스트·토큰’처럼 범위가 문맥에 따라 달라지는 용어를 단순 대응표로 바꾸지 않는다. 외래어를 살리려고 설명이 필요한 독자를 방치하지도 않는다.

문장별로 **누가, 무엇을, 언제, 어떤 조건에서, 어느 정도로, 해야/할 수/했다는 것인지** 대조한다. 숫자가 그대로여도 비교 기준이나 분모가 바뀌면 의미가 달라진다. 부정어를 남겼더라도 부정의 범위가 달라지면 실패다.

직접 인용, 법조문, 고유명사, 코드, 수식은 원문을 유지하고 의심되는 오류는 바깥에서 설명한다. 핵심 개념의 구별을 유지하되, 같은 낱말을 반드시 남기는 방식만으로 의미 보존을 판정하지 않는다. 일반 독자를 위한 풀이를 제안할 때는 용어의 의미와 적용 범위를 유지한다.

## 일괄 적용하지 않는 것

- AI 작성 여부·확률, ‘AI 같은 표현’만을 이유로 한 오류 판정
- 특정 표현의 고정 횟수 제한과 패턴 잔존 0개 목표
- 100자 이상 문장 추가 등 리듬의 정량 목표
- 수정률 30%·50%에 따른 일괄 경고·중단
- 수정 이유 없이 전체 글을 윤문하는 동작

이러한 지표가 있더라도 검토 단서는 될 수 있지만 정확성이나 품질의 증거를 대신하지 않는다. 의미 손상은 짧은 단어 하나의 변경으로도 발생한다.
